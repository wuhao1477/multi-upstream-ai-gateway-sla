## 1. 项目概述

### 1.1 背景

业务计划将约 20 个 AI 上游渠道统一接入一个网关。上游可能使用 NewAPI、Sub2API、其他开源系统或二次开发系统，并通过不同账号、Key、用户组和倍率提供模型服务。

同一模型在不同渠道上的价格、首字响应、完整响应成功率、缓存表现、余额、容量和稳定性差异明显，并可能随时变化。部分渠道采用按月或按固定周期订阅，包含到期作废的额度，但其倍率和实际成功成本不一定具有优势。固定权重、单纯选择最低价格或无条件优先订阅渠道，都无法持续保障用户体验和服务可用性。

### 1.2 产品目标

网关根据渠道的实时状态动态分配请求，按以下顺序做出业务决策：

1. 数据与租户许可满足要求。
2. 模型及请求能力完全兼容。
3. 账号余额、Key 额度和渠道容量足够。
4. 渠道健康，且不违反对应 SLA 等级的故障域限制。
5. 连续会话的延迟与缓存目标可满足。
6. 在以上条件均满足时，综合预计实际成功成本、订阅额度到期风险和可利用空间选择渠道。
7. 订阅渠道只能在成本限制内提高优先级，不得因额度临近到期绕过 SLA、缓存、容量或成本条件。
8. 在独立试错预算内，用少量真实业务流量持续评估低权重或恢复中的渠道。

价格不得抵消安全、能力、余额或可用性等硬性条件。

### 1.3 预期业务结果

- 对外提供可定义、可测量、可追溯的 SLA。
- 连续对话的首字体验保持在业务目标内；初始参考目标为前缀平均首字时间不超过 10 秒。
- 适用场景下，可缓存输入 Token 的缓存命中率达到 90% 以上。
- 在满足 SLA 的前提下，降低每次完整成功响应的实际成本。
- 在成本限制内提高订阅额度的有效利用率，减少可避免的到期未用额度；不得通过失败请求或无业务价值请求消耗额度。
- 在价格、余额、性能或稳定性变化后，按异常处置规则调整新请求分配。
- 任一调度、测活、接管和人工操作均能解释原因并追溯结果。

> 10 秒和 90% 为当前产品目标，不自动构成正式合同承诺。各业务等级的最终 SLA 数值须在开发计划启动前确认。

### 1.4 策略配置化总原则（v1.2 新增）

本系统面向的是"渠道本身不稳定"的使用场景，不同使用者圈定的渠道差异极大，因此**所有调度与经营策略参数不得写死**。统一遵循：

- 每项策略以本文档给出的建议值作为**出厂默认值**，并在管理设置中**可查看、可修改**。
- 设置界面必须**明示每项策略的含义、用法和修改影响**。
- 对安全和成本影响重大的关键策略（测活预算、禁测活规则、订阅倾斜上限、旁路开关等），修改需**二次确认**，确认使用者理解设计后方可保存。
- 具体可配置项及默认值见第 11 节与第 13 节。

## 2. 范围

### 2.1 需求范围与交付分期

> **本节是交付分期的唯一真相源**（2026-07-25 确认）。下游的里程碑（[dev/00](./dev/00-overview-and-milestones.md)）、验收矩阵（[dev/14](./dev/14-acceptance-matrix.md)）、范围说明（[dev/15](./dev/15-scope-and-preflight.md)）**必须与本表一致**；如有冲突以本表为准。
>
> **分期不降低需求标准**：下列全部条目仍是本产品的正式需求，仅交付时序不同。

#### 一期（SLA 自研网关：智能调控 + SLA 保障）

- 渠道、真实上游、账号、Key、模型和故障域管理。
- 模型价格、用户组倍率、Key 倍率及实际扣费管理（**普通渠道成本口径**）。
- 账号余额、Key 额度、周期限额、容量和可持续时间管理。
- 首字响应、完整成功、流中断、限流评估。
- 连续会话延迟预算、**会话粘性**与动态渠道分配。
- 首字前接管、重试限制和重复费用统计。
- **新渠道受控验证（canary）**：把本就要发的低等级请求按硬上限分给待验证渠道，使其在不制造故障的前提下积累首批样本（FR-121）。
- SLA（**单等级**，结构预留多级）、错误预算、成本、余额和渠道状态记录。
- 数据使用规则（**默认全放行**）、权限控制、人工停用和审计追踪。
- 对外提供 OpenAI Chat Completions 与 Responses 两种协议格式，支持流式与工具调用透传。
- 面向异构上游家族（NewAPI 系、Sub2API 系、闭源自建平台）的**价格/余额/Key 额度**采集与站型探测。
- 调度与经营策略的配置化管理（见 1.4）。
- 自研决策核心自身的可用性、时延与多实例可靠性要求。

#### 二期（交付时序推迟，需求不降级）

### 2.2 不在本期范围

- 开发任务拆分、排期、人员安排和工作量估算。
- 技术架构、技术栈、存储方案、部署方案和接口设计。
- 自动充值、订阅采购或续费、付款、发票和对外计费系统。
- 自建模型、训练、微调或提示词优化。
- 未经业务授权的自动模型降级。
- 管理后台的页面原型与交互设计。

### 2.3 业务前置条件

- 上游渠道已取得合法使用授权，并明确代理、数据处理和自动调用限制。
- 每个渠道至少提供可验证的价格、余额、订阅有效期、订阅额度或实际扣费依据；无法自动查询时由运营维护并标记来源。
- 业务能够为请求提供模型、SLA 等级及是否允许测活等分类信息（数据级别与租户分类在个人/内部场景下为可选，见 FR-093）。
- 第 13 节所列业务参数已于 2026-07-22 完成确认（见 [决策确认记录](./DECISIONS.md)），本文档默认值即确认结果。

### 2.4 使用场景与由此确定的边界（v1.2 明确）

本系统为**个人 / 内部使用，不对外提供服务**，由此确定若干边界：

- 许可证：一期**上游对接为自研**，不依赖第三方网关，无引入外部 copyleft 组件的义务问题；调研阶段仅借鉴思路不复制代码（见 [11 转向决策](./dev/11-decision-full-selfbuilt.md)）。
- 数据合规：不强制多租户数据分级与地区隔离（FR-093 由硬性降为可选）。
- 安全：上游 Key 一期明文存储可接受（见 FR-113）。
- 规模：按峰值 100～1000 QPS 设计与验证（见 FR-114）；容量验收为**并发门禁 + 吞吐门禁**双轨（AC-34/AC-36）。

## 3. 核心术语

| 术语 | 定义 |
| --- | --- |
| 渠道 | 一个可配置的上游服务入口，可包含多个账号和 Key。 |
| 真实上游 | 最终提供模型能力的官方供应商或实际服务源。 |
| 路由资源 | 可独立评估和分配请求的最小业务对象，由渠道、账号、Key、模型、地区及缓存作用域共同确定。 |
| 有效首字 | 用户收到的第一个有效模型内容；连接事件、空白心跳不计入。 |
| 完整成功 | 返回满足请求能力和协议要求的完整结果；首字后中断不算成功。 |
| 连续会话 | 多轮共享上下文，需要保持模型能力和缓存连续性的对话。 |
| 前缀平均首字时间 | 从会话第一轮到当前轮的全部实际首字时间平均值。 |
| 缓存命中率 | 命中缓存的可缓存输入 Token 占全部可缓存输入 Token 的比例。 |
| 实际成功成本 | 获得完整成功响应所产生的主请求、失败、重试、接管及未取消重复请求费用之和。 |
| 业务测活 | 使用符合条件的真实业务请求评估未知、低权重或恢复中的路由资源。 |
| 接管 | 原资源尚未输出有效首字时，由稳定资源重新承担请求。 |
| 故障域 | 可能因同一原因同时失效的一组资源，如同一官方供应商、代理层、账号、地区或网络。 |
| 错误预算 | 在指定统计周期内允许发生的失败、超时或延迟超标额度。 |
| 订阅计划 | 在固定有效期内提供额度或使用权的上游方案，可包含倍率、模型范围、周期重置和超额计费规则。 |
| 可利用订阅额度 | 在订阅有效期内，满足模型、数据、SLA、容量和成本条件，预计能够由真实业务安全消耗的剩余额度。 |
| 预计到期未用额度 | 当前剩余订阅额度扣除到期前预计合格业务消耗量后的正值，用于衡量潜在额度损失。 |
| 用满倍率 | 假设订阅包含额度在有效期内被全部有效消耗时的边际成本倍率＝固定费用 ÷ 周期包含额度 ×（如有）分组/Key 倍率。用于**调度排序**，反映"若用满则单位成本"。 |
| 实际倍率 | 按订阅当前真实消耗重算的成本倍率＝固定费用 ÷ 实际消耗额度 × 倍率。用于**账务与报表**。因固定费用已付，未用满时实际倍率高于用满倍率，故不得用实际倍率给未用满的订阅渠道降权。 |
| 额度来源优先级 | 某些上游平台自身规定额度消耗顺序（如先扣订阅、后扣现金余额）。采集需读取该顺序，据此判断订阅额度是否真会被消耗。 |
| 可主动重置额度 | 某些平台允许在满足条件（如当日用量超阈值）时手动重置周期额度，构成可争取的额外额度，纳入到期未用预测的外生变量。 |
| 模型别名 | 对外暴露的、承载调度策略的模型名（如 `gpt-5.5-sla-1`）。别名映射到一套具体策略（SLA 等级、是否允许测活等），调用方通过选择别名选择策略。 |
| 站型家族 | 上游站点所属的接口家族：NewAPI 系、Sub2API 系、闭源自建平台等。同族站点可复用同一采集适配器，跨族不可复用。 |

## 5. SLA 与经营指标

### 5.1 对外服务指标

| 指标 | 统一定义 |
| --- | --- |
| 有效可用性 | 完整成功请求数 ÷ 应计入 SLA 的有效请求数。上游失败、超时和网关错误计入失败；用户参数错误和用户主动取消不计入。 |
| 首字 P95/P99 | 从网关接受有效请求到输出有效首字的 P95/P99 时间，包含排队和接管时间。 |
| 完整响应成功率 | 完整结束且满足请求能力要求的请求占比。 |
| 流中断率 | 已输出有效首字但未完整结束的流式请求占比。 |
| 会话前缀平均达标率 | 每轮结束时，前缀平均首字时间达到目标的会话节点占比。 |

### 5.2 内部经营指标

| 指标 | 统一定义 |
| --- | --- |
| Token 加权缓存率 | 缓存命中的可缓存输入 Token ÷ 全部可缓存输入 Token。 |
| 实际成功响应成本 | 全部相关请求费用 ÷ 完整成功响应数。 |
| 余额可持续时间 | 当前可路由余额 ÷ 近期实际费用消耗速度。 |
| 测活成功率 | 完整成功的测活请求 ÷ 全部测活请求。 |
| 接管率 | 触发稳定资源接管的请求 ÷ 全部请求。 |
| 价格新鲜度 | 当前时间距最近一次可信价格确认的时长。 |
| 订阅额度消耗率 | 上游确认的本周期已消耗包含额度 ÷ 本周期包含额度。 |
| 订阅额度有效利用率 | 用于完整成功响应的包含额度 ÷ 本周期包含额度；失败和无业务价值消耗不计入有效利用。 |
| 预计到期未用额度 | 各订阅计划在当前预测下到期仍无法由合格业务消耗的额度。 |

### 5.3 统计规则

- 所有指标必须明确统计周期、模型、请求类型、租户和 SLA 等级。
- 平均值不能替代 P95/P99、失败率和会话节点指标。
- 测活、接管和重试造成的真实用户延迟与失败必须计入对外指标。
- 测活费用可以由独立探索预算承担，但不得从实际成本中删除。
- 订阅额度消耗率和有效利用率必须分开统计，不能以无效消耗提高有效利用率。
- 订阅指标必须按订阅计划和计费周期统计，并区分包含额度与超额付费消耗。
- 指标需支持总体、渠道、路由资源、故障域、租户和会话维度查看。

## 6. 端到端业务流程

每次请求按以下流程处理：

1. **请求分类**：识别模型、上下文、工具调用、多模态、数据级别、租户和 SLA 等级。
2. **资格过滤**：排除数据不允许、能力不匹配、余额不足、额度耗尽、订阅失效、容量不足或已停用的资源。
3. **风险过滤**：排除健康度不足、故障相关性过高、价格或余额无法安全判断的资源。
4. **会话判断**：评估本轮选择对前缀平均首字时间和缓存率的影响。
5. **成本选择**：从剩余资源中综合预计实际成功成本、订阅到期风险和可利用空间选择资源；任何订阅优先均受成本限制。
6. **测活判断**：仅在满足全部条件及预算时，将请求分配给待验证资源。
7. **响应保障**：原资源首字前超出允许等待时间时，可由稳定资源接管。
8. **结果结算**：记录实际延迟、完整状态、缓存、费用、余额变化、订阅额度变化和接管情况。
9. **状态更新**：更新资源健康度、价格可信度、余额状态、冷却时间和后续流量资格。

## 8. 关键业务规则

### 8.1 会话延迟预算

```text
会话延迟余量 = 目标首字时间 × 已完成轮数 - 累计实际首字时间
```

- 快速请求形成余量，慢请求消耗余量。
- 选择慢渠道前必须保留安全余量，并使用近期高分位首字时间预测。
- 用户可能在任意一轮结束对话，因此每轮后的前缀平均值都必须受控。

### 8.2 缓存率

```text
缓存命中率 = 缓存命中的可缓存输入 Token ÷ 全部可缓存输入 Token
```

- 不按请求次数计算。
- 渠道切号或更换缓存作用域造成的损失必须计入。
- 当延迟目标和缓存目标冲突时，按业务配置的 SLA 优先级处理并记录原因。

### 8.3 可路由余额

```text
可路由余额 = 最近确认的可用余额 - 未结算请求预留费用 - 安全储备
```

- 账号余额和 Key 额度分别判断，任一不足都不可继续分配。
- 共享账号余额只计算一次。
- 余额数据过期时必须扣除已知消耗；无法得出安全下限时停止新请求。

### 8.4 实际成功成本

```text
实际成功成本 = 主请求费用 + 订阅固定费用分摊 + 失败费用 + 重试费用 + 接管费用 + 未取消重复费用
```

- 成本比较以完整成功响应为单位。
- 官方标称倍率只作为输入，不能替代实际扣费。

### 8.5 订阅渠道调度

```text
预计到期未用额度 = max(0, 当前剩余订阅额度 - 到期前预计合格业务消耗量)
```

- 订阅优先只在已通过安全、能力、余额、健康、容量、会话延迟和缓存条件的候选资源中生效。
- 到期时间越近、预计到期未用额度越高且合格业务需求越充足，订阅渠道可以在配置范围内提高优先级。
- 订阅费用已经支付不代表本次请求成本为零；固定费用应按已确认规则分摊，倍率、超额费用、失败、缓存损失、重试和接管费用仍计入预计实际成功成本。
- **双倍率规则**：调度排序用"用满倍率"（固定费用÷周期额度×倍率），使未用满的订阅渠道不因固定费用摊高的实际均价而被错误降权；账务与报表用"实际倍率"（按真实消耗重算）。例：用满 0.034、当前实际 0.045 的订阅渠道，其调度优先级应高于倍率 0.035 的普通渠道。
- 提高订阅流量不得超过单次请求、租户、模型、SLA 等级或统计周期的适用成本上限，也不得占用接管保留容量。
- 当订阅渠道性能、稳定性、缓存或倍率不具优势时，应限制其优先级；临近到期不能成为违反成本限制或降低 SLA 的理由。
- 无法安全利用的额度允许到期，必须记录不可利用原因；不得通过虚构请求、无业务价值请求或放宽完整成功标准消耗额度。
- 读取平台自身的**额度来源优先级**判断订阅额度是否真会被消耗；对支持**主动重置额度**的平台，将可争取的额外额度纳入到期未用预测。

### 8.6 价格变化

- 涨价：可信确认后立即限制新增流量。
- 降价：再次确认或用真实扣费验证后逐步增加流量。
- 查询失败：保留最后可信版本并降低新鲜度；不能形成保守价格时退出成本优选。
- 扣费异常：停止低价优选，待价格和账单重新确认后恢复。

### 8.7 测活再次准入

```text
冷却结束
且价格与余额有效
且探索预算充足
且会话能够承受
且稳定资源保有接管容量
```

任何一项不满足，均不得再次测活。

## 9. 状态定义

### 9.1 健康状态

| 状态 | 可执行动作 |
| --- | --- |
| 未知 | 不作为稳定资源，仅等待资料完善或进入观察。 |
| 观察 | 仅允许受限测活。 |
| 可用 | 可参加正常调度。 |
| 降级 | 限制流量，不作为优先接管资源。 |
| 冷却 | 禁止测活和正常新增流量，等待条件恢复。 |
| 停用 | 禁止新增请求，仅保留历史和审计。 |

### 9.2 余额状态

| 状态 | 处理要求 |
| --- | --- |
| 正常 | 正常参与调度。 |
| 临界 | 停止测活和高成本请求，减少普通流量。 |
| 未知 | 使用保守下限；无法确认安全余额时停止新请求。 |
| 耗尽 | 立即停止新增请求。 |
| 异常 | 停止成本优选并等待人工或自动复核。 |

### 9.3 订阅状态

| 状态 | 处理要求 |
| --- | --- |
| 未生效 | 不参与调度。 |
| 有效 | 按正常资格和成本规则参与调度。 |
| 临近到期 | 评估预计到期未用额度，仅在成本和引流上限内提高使用比例。 |
| 数据未知 | 不执行到期优先；无法确认仍有效时停止使用订阅额度。 |
| 已到期 | 立即停止使用已失效额度；存在超额计费时按普通付费资源重新判断资格。 |

## 10. 异常处置矩阵

| 异常 | 默认处理 | 恢复条件 |
| --- | --- | --- |
| 价格上涨 | 限制新增流量，更新成本预测 | 新价格确认完成 |
| 价格下降 | 保持原流量，不立即迁移 | 再次确认或实际扣费验证 |
| 价格数据过期 | 使用保守价格；无法估计则退出成本优选 | 获取可信价格 |
| 订阅临近到期且预计存在未用额度 | 在合格候选中、成本和引流上限内逐步提高使用比例 | 额度已有效利用、预测不再存在损失或订阅到期 |
| 订阅临近到期但倍率、性能或稳定性不满足要求 | 不提高优先级，记录不可利用原因和预计损失 | 相关条件恢复且仍处于有效期内 |
| 订阅额度数据过期或共享关系不明 | 按保守额度参与调度，不执行到期优先 | 获取可信额度并确认共享关系 |
| 余额临界 | 停止测活和高成本请求，逐步减少流量 | 可持续时间恢复到安全范围 |
| Key 额度耗尽 | 立即停止该 Key 新请求 | 额度重置或人工恢复 |
| Key 失效或权限不足 | 立即停止该 Key 新请求并告警 | Key 状态与目标模型权限重新验证通过 |
| 实际扣费异常 | 停止低价优选，保留必要 SLA 流量或直接停用 | 价格与扣费复核通过 |
| 首字持续变慢 | 降低流量并消耗错误预算 | 观察期内性能恢复 |
| 首字后中断 | 记为完整失败，不拼接其他模型输出 | 后续请求重新选择资源 |
| 测活超时 | 首字前由稳定资源接管，测活资源进入冷却 | 冷却、预算和容量均恢复 |
| 同故障域集中失败 | 同时限制相关资源 | 故障域恢复并通过观察 |
| 模型或能力不符 | 立即排除该资源 | 能力重新验证通过 |
| 全部合规资源不可用 | 返回明确不可用结果并告警 | 至少一个合规资源恢复 |

## 12. 验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 配置 20 个渠道及其账号、Key、模型和故障域 | 可完整查询每个路由资源的身份、能力、状态和关系。 |
| AC-02 | 某渠道模型价格上涨 | 新请求按新价格重新判断；历史请求仍按原版本复算。 |
| AC-03 | 某渠道价格下降但尚未验证 | 不立即集中迁移；验证后才逐步增加流量。 |
| AC-04 | 多个 Key 共享账号余额且存在并发请求 | 余额不重复计算，进行中费用被预留，不发生可预见超支。 |
| AC-05 | 账号有余额但目标 Key 日额度耗尽 | 该 Key 被排除，其他合格资源仍可参与调度。 |
| AC-06 | A 渠道约 20 秒且低价，B 渠道约 3 秒且较贵 | 系统根据会话前缀平均值和安全余量分配，预算不足时使用 B 恢复。 |
| AC-07 | 切换低价渠道会使缓存率低于目标 | 系统限制切换，或因更高优先级 SLA 切换并记录原因。 |
| AC-08 | 低权重渠道长期无样本 → 受控验证闭环 | **一期（FR-121）**：样本不足即标记低可信、不作稳定主力渠道；新登记与冷却期满渠道须能在**不发生全局故障**的前提下，靠受控 canary 走完"验证中 → 观察期 → 可用"，且硬上限（每小时次数、并发、仅低等级、须有接管候选）在多实例并发下**不被突破**。⏭ **二期**（随主动测活）：在模型/数据/余额/预算/接管条件均满足时获得有限的额外测活机会。 |
| AC-09 | 测活渠道首字超时 | 稳定资源在首字前接管；延迟计入 SLA，费用计入探索预算和实际成本。 |
| AC-10 | 测活渠道失败或费用超标 | 进入冷却；仅在冷却结束且预算充足时再次获得机会。 |
| AC-11 | 多个渠道实际共享同一官方上游并同时故障 | 系统识别共同故障，不在相关资源之间反复接管。 |
| AC-12 | 已输出首字后发生流中断（两种成因：上游断流 / 网关进程自身崩溃） | 两者都记为**完整失败**、都计入用户 SLA 失败（FR-071），都不拼接另一模型内容。**流中断率的口径更窄**：只统计"已确认写出过内容之后才中断"的请求——网关崩溃在"内容尚未确认写出"之前的，计入失败但**不计流中断**。二者在账本中保留可区分的终态以便归因（上游的问题 vs 我们的问题）。 |
| AC-13 | 请求包含不可重复的外部写入操作 | 不自动并发测活或盲目重试。 |
| AC-14 | 渠道不满足租户数据许可但价格最低 | 在价格比较前被排除。 |
| AC-15 | 全部合规资源不可用 | 返回明确不可用结果，不自动降级模型或使用不合规渠道。 |
| AC-16 | 查询任一历史请求 | 可看到当时的候选、排除原因、价格、余额、选择、延迟、费用和接管记录。 |
| AC-17 | 两个渠道使用不同币种或计费单位 | 系统统一以美元口径比较，一期各币种按 1:1 处理（币种仅名称）；不同额度单位由采集适配器归一为数值。 |
| AC-18 | 单一租户流量突增 | 不占用接管保留容量，受限流量按已配置规则处理。⏭ 测活并发部分随主动测活移二期。 |
| AC-19 | 余额耗尽、Key 失效或错误预算快速消耗 | 立即产生包含影响范围和处置建议的告警，并持续记录到恢复关闭。 |
| AC-20 | 某订阅渠道临近到期，预计存在较多未用额度，且其 SLA、缓存、容量和成本均满足限制 | 系统在订阅引流上限内逐步增加合格业务流量，并记录到期紧迫度、成本判断和额度变化。 |
| AC-21 | 某订阅渠道临近到期，但倍率较高或性能、稳定性、缓存表现不满足限制 | 系统不因订阅即将到期而无条件优先，记录未使用原因和预计到期损失。 |
| AC-22 | 多个账号或 Key 共享同一订阅额度 | 系统只计算一次剩余额度，基于共享额度预测到期未用量，不发生重复分配或超额使用。 |
| AC-23 | 增加订阅渠道流量将触发超额计费或突破适用成本上限 | 系统停止增加该渠道流量，保留真实成本记录，不以提高额度消耗率为由继续使用。 |
| AC-24 | 一个用满倍率 0.034、实际倍率 0.045 的订阅渠道，与一个倍率 0.035 的普通渠道竞争 | 调度按用满倍率排序，订阅渠道优先级更高；账务报表按实际倍率 0.045 记账。 |
| AC-25 | 调用方分别使用 `gpt-5.5`（可测活别名）与 `gpt-5.5-sla-1`（禁测活别名）发起相同请求 | 前者可被分配测活，后者不参与任何测活，两者适用各自别名映射的 SLA 策略。 |
| AC-26 | 客户端以 OpenAI Chat Completions 与 Responses 两种格式发起流式、含工具调用的请求 | 两种协议均正确透传流式、工具调用与多模态字段并完整回传。 |
| AC-27 | 自研决策核心某一实例宕机 | 其余实例继续服务不中断；核心整体不可用时返回明确错误，不绕过策略直连上游。 |
| AC-28 | 三个不同家族站点（NewAPI、Sub2API、闭源自建）接入采集 | 系统按公开端点探测出各自站型并套用对应适配器；无接口字段按人工录入并标注来源、7 天有效期。 |
| AC-29 | 某渠道以非标准方式返回"余额不足"（错误文案或状态码各异） | 信号识别框架据文案关键词/失败信号/余量归零判定并将资源置为耗尽，停止新付费请求。 |
| AC-30 | 同一请求经历客户端断开、上游中途断开、网关内部超时转移三种中断 | 账本按 `errorMessage` 归并"取消"口径而非仅看网关 `status` 枚举（网关 `canceled` 仅指客户端取消，上游断开/内部超时归 `failed`），三者均关联同一请求可对账。 |
| AC-31 | 上游先发 role-only 元事件（或空 SSE、心跳注释），0.5 秒后才发首个可见内容 | 首字时间按"有效首字"（首个可见内容）由自研核心**旁路观察自算**，**不采信任何上游或中间层回传的首字/首字节字段**（历史实测：多个网关实现均把元事件当首字节）。 |
| AC-32 | 已输出有效首字的流式请求在中途被取消 | 自研上游对接层将取消传播到上游、主动拆除上游连接以止损用量（上游随即停止生成）。 |
| AC-33 | 调用方无凭证 / 使用已吊销凭证 / 请求越权别名 / 超出配额访问 `/v1/*` | 分别返回 401 / 401 / 403 / 429；**入站凭证只存哈希**，管理接口与日志永不回显完整凭证；**严禁复用上游 Key 作为入站凭证**。 |
| AC-34 | 自研核心在 1000 并发用户高强度持续使用下运行 | 稳态期决策开销 P99 ≤50 毫秒、错误率 <0.01%，内存不持续增长、连接与协程在压测结束后回落基线，无 OOM 或句柄耗尽；另须探测并记录容量拐点。 |
| AC-36 | 系统承受峰值吞吐 | 峰值 **1000 QPS 持续 60 秒**（mock 上游、90% 流式），决策开销 P99 ≤50 毫秒、错误率 <0.1%，无 OOM 与句柄耗尽。 |
| AC-35 | 进程在「上游调用前 / 已发出但无任何结果 / 首字已记录但未写出 / 已写出部分内容 / 上游结果已记录但未写完 / 全部写完」各时点崩溃并重启 | 账本不得出现「请求完全不存在」、不得永久停留待定；每个时点的账本终态、配额预留终态与**下游实际收到的字节**三者必须自洽：未写出任何内容的判为失败且**不计流中断**，写出过部分内容的判为流中断，上游已失败的**不得**记成渠道成功。未投递的账本事件重启后被重放且不产生重复。**注**：系统只能确认「已写出到下游连接」，无法确认「客户端已收到」——后者需要客户端应用层回执，而主力客户端不可要求配合，该残余不确定性已知并接受。 |

## 13. 业务参数确认结果

原 16 项待确认参数已于 2026-07-22 全部确认（完整逐项记录见 [决策确认记录](./DECISIONS.md)）。下表为确认摘要，具体默认值见第 11 节，全部可配置。

| 参数 | 确认结果 |
| --- | --- |
| SLA 指标与统计周期 | **完全可配置**：等级数量、各项指标数值、统计窗口均由使用者自定义；金/银/铜三级建议数值仅作默认模板 |
| SLA/缓存/成本冲突优先级 | **可配置**：每等级取舍顺序自定义；默认金 SLA>缓存>成本、银 SLA>成本>缓存、铜 成本>缓存>SLA |
| 测活预算上限 | 采纳建议（全局 2%+日封顶、租户 2%、会话 1 次、失败≤错误预算 10%）；可配置，修改需二次确认 |
| 严格补偿 / 预算延续 | 默认严格补偿；可在设置中切换为预算延续，由使用者决定 |
| 余额安全储备 | 采纳建议公式与三档处置；**余额非实时**，改为"余额不足"信号自适应识别（FR-027）；可配置 |
| 禁测活范围 | **不用条件清单**，改由模型别名控制测活资格（FR-062）；并发重试默认全局禁止（FR-079） |
| 全渠道不可用行为 | 采纳（金 15s / 银 5s / 铜 0s）；可配置 |
| 渠道数据许可 | **取消默认白名单**，个人/内部场景默认全允许；数据分级降为可选（FR-093） |
| 统一币种与汇率 | 统一美元口径，不建动态汇率系统（FR-018） |
| 数据查询周期与过期 | 采纳建议默认值；可配置并说明影响（FR-116） |
| 样本门槛、观察期、冷却 | 采纳建议默认值；**必须可配置**（渠道普遍不稳定，建议值不通用） |
| 容量保留规则 | 采纳（金级 20%、测活≤5%、接管保留 10%）；可配置 |
| 订阅台账字段 | 采纳建议字段，另加用满倍率、实际倍率、额度来源优先级、可主动重置额度（FR-033） |
| 订阅固定费用分摊 | 双倍率设计：用满倍率调度、实际倍率账务（FR-057/058、8.5） |
| 订阅成本/引流/到期上限 | 采纳（1.5 倍成本、40% 引流、7 天+20% 启动） |
| 告警分级与响应时限 | 采纳（P1 15min / P2 1h / P3 当日）；可配置 |
