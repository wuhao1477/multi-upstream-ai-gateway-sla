## 1. 项目概述

### 1.1 背景

业务计划将约 20 个 AI 上游渠道统一接入一个网关。上游可能使用 NewAPI、Sub2API、其他开源系统或二次开发系统，并通过不同账号、Key、用户组和倍率提供模型服务。

同一模型在不同渠道上的价格、首字响应、完整响应成功率、缓存表现、余额、容量和稳定性差异明显，并可能随时变化。固定权重或单纯选择最低价格，无法持续保障用户体验和服务可用性。

### 1.2 产品目标

网关根据渠道的实时状态动态分配请求，按以下顺序做出业务决策：

1. 数据与租户许可满足要求。
2. 模型及请求能力完全兼容。
3. 账号余额、Key 额度和渠道容量足够。
4. 渠道健康，且不违反对应 SLA 等级的故障域限制。
5. 连续会话的延迟与缓存目标可满足。
6. 在以上条件均满足时，选择预计实际成功成本更低的渠道。
7. 在独立试错预算内，用少量真实业务流量持续评估低权重或恢复中的渠道。

价格不得抵消安全、能力、余额或可用性等硬性条件。

### 1.3 预期业务结果

- 对外提供可定义、可测量、可追溯的 SLA。
- 连续对话的首字体验保持在业务目标内；初始参考目标为前缀平均首字时间不超过 10 秒。
- 适用场景下，可缓存输入 Token 的缓存命中率达到 90% 以上。
- 在满足 SLA 的前提下，降低每次完整成功响应的实际成本。
- 在价格、余额、性能或稳定性变化后，按异常处置规则调整新请求分配。
- 任一调度、测活、接管和人工操作均能解释原因并追溯结果。

> 10 秒和 90% 为当前产品目标，不自动构成正式合同承诺。各业务等级的最终 SLA 数值须在开发计划启动前确认。

## 2. 范围

### 2.1 本期范围

- 渠道、真实上游、账号、Key、模型和故障域管理。
- 模型价格、用户组倍率、Key 倍率及实际扣费管理。
- 账号余额、Key 额度、周期限额、容量和可持续时间管理。
- 首字响应、完整成功、流中断、限流和缓存表现评估。
- 连续会话延迟预算、缓存亲和性和动态渠道分配。
- 基于真实业务流量的无缝测活、冷却和再次试错。
- 首字前接管、重试限制和重复费用统计。
- SLA、错误预算、成本、余额和渠道状态报表。
- 数据使用规则、权限控制、人工停用和审计追踪。

### 2.2 不在本期范围

- 开发任务拆分、排期、人员安排和工作量估算。
- 技术架构、技术栈、存储方案、部署方案和接口设计。
- 自动充值、付款、采购、发票和对外计费系统。
- 自建模型、训练、微调或提示词优化。
- 未经业务授权的自动模型降级。
- 管理后台的页面原型与交互设计。

### 2.3 业务前置条件

- 上游渠道已取得合法使用授权，并明确代理、数据处理和自动调用限制。
- 每个渠道至少提供可验证的价格、余额或实际扣费依据；无法自动查询时由运营维护并标记来源。
- 业务能够为请求提供模型、数据级别、租户、SLA 等级及是否允许测活等分类信息。
- 产品、SLA、成本和安全负责人共同确认第 13 节所列业务参数。

## 3. 核心术语

| 术语 | 定义 |
| --- | --- |
| 渠道 | 一个可配置的上游服务入口，可包含多个账号和 Key。 |
| 真实上游 | 最终提供模型能力的官方供应商或实际服务源。 |
| 路由资源 | 可独立评估和分配请求的最小业务对象，由渠道、账号、Key、模型、地区及缓存作用域共同确定。 |
| 有效首字 | 用户收到的第一个有效模型内容；连接事件、空白心跳不计入。 |
| 完整成功 | 返回满足请求能力和协议要求的完整结果；首字后中断不算成功。 |
| 连续会话 | 多轮共享上下文，需要保持模型能力和缓存连续性的对话。 |
| 前缀平均首字时间 | 从会话第一轮到当前轮的全部实际首字时间平均值。 |
| 缓存命中率 | 命中缓存的可缓存输入 Token 占全部可缓存输入 Token 的比例。 |
| 实际成功成本 | 获得完整成功响应所产生的主请求、失败、重试、接管及未取消重复请求费用之和。 |
| 业务测活 | 使用符合条件的真实业务请求评估未知、低权重或恢复中的路由资源。 |
| 接管 | 原资源尚未输出有效首字时，由稳定资源重新承担请求。 |
| 故障域 | 可能因同一原因同时失效的一组资源，如同一官方供应商、代理层、账号、地区或网络。 |
| 错误预算 | 在指定统计周期内允许发生的失败、超时或延迟超标额度。 |

## 5. SLA 与经营指标

### 5.1 对外服务指标

| 指标 | 统一定义 |
| --- | --- |
| 有效可用性 | 完整成功请求数 ÷ 应计入 SLA 的有效请求数。上游失败、超时和网关错误计入失败；用户参数错误和用户主动取消不计入。 |
| 首字 P95/P99 | 从网关接受有效请求到输出有效首字的 P95/P99 时间，包含排队和接管时间。 |
| 完整响应成功率 | 完整结束且满足请求能力要求的请求占比。 |
| 流中断率 | 已输出有效首字但未完整结束的流式请求占比。 |
| 会话前缀平均达标率 | 每轮结束时，前缀平均首字时间达到目标的会话节点占比。 |

### 5.2 内部经营指标

| 指标 | 统一定义 |
| --- | --- |
| Token 加权缓存率 | 缓存命中的可缓存输入 Token ÷ 全部可缓存输入 Token。 |
| 实际成功响应成本 | 全部相关请求费用 ÷ 完整成功响应数。 |
| 余额可持续时间 | 当前可路由余额 ÷ 近期实际费用消耗速度。 |
| 测活成功率 | 完整成功的测活请求 ÷ 全部测活请求。 |
| 接管率 | 触发稳定资源接管的请求 ÷ 全部请求。 |
| 价格新鲜度 | 当前时间距最近一次可信价格确认的时长。 |

### 5.3 统计规则

- 所有指标必须明确统计周期、模型、请求类型、租户和 SLA 等级。
- 平均值不能替代 P95/P99、失败率和会话节点指标。
- 测活、接管和重试造成的真实用户延迟与失败必须计入对外指标。
- 测活费用可以由独立探索预算承担，但不得从实际成本中删除。
- 指标需支持总体、渠道、路由资源、故障域、租户和会话维度查看。

## 6. 端到端业务流程

每次请求按以下流程处理：

1. **请求分类**：识别模型、上下文、工具调用、多模态、数据级别、租户和 SLA 等级。
2. **资格过滤**：排除数据不允许、能力不匹配、余额不足、额度耗尽、容量不足或已停用的资源。
3. **风险过滤**：排除健康度不足、故障相关性过高、价格或余额无法安全判断的资源。
4. **会话判断**：评估本轮选择对前缀平均首字时间和缓存率的影响。
5. **成本选择**：从剩余资源中选择预计实际成功成本更低者。
6. **测活判断**：仅在满足全部条件及预算时，将请求分配给待验证资源。
7. **响应保障**：原资源首字前超出允许等待时间时，可由稳定资源接管。
8. **结果结算**：记录实际延迟、完整状态、缓存、费用、余额变化和接管情况。
9. **状态更新**：更新资源健康度、价格可信度、余额状态、冷却时间和后续流量资格。

## 7. 产品需求

需求优先级：`P0` 为 SLA 基础能力，缺失则不能提供正式服务；`P1` 为运营与优化能力，可在 P0 稳定后启用。

### 7.1 渠道与能力管理

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-001 | P0 | 支持管理至少 20 个渠道，并可持续新增、停用和恢复。 |
| FR-002 | P0 | 分别登记渠道、真实上游、账号、Key、用户组、模型、地区和缓存作用域，不以渠道名称代替实际资源身份。 |
| FR-003 | P0 | 支持一个账号共享多个 Key，以及 Key 具有独立倍率、额度或模型权限。 |
| FR-004 | P0 | 在渠道、账号、Key、模型和故障域层级控制是否允许接收新请求。 |
| FR-005 | P0 | 记录每个资源实际支持的模型版本、最大上下文、流式输出、工具调用、结构化输出、多模态和推理能力。 |
| FR-006 | P0 | 请求所需能力不完整时直接排除该资源；未经授权不得自动替换模型或降低能力。 |
| FR-007 | P1 | 记录空响应、格式破坏、能力不符和疑似模型替换等质量事件。 |

### 7.2 价格、倍率与实际扣费

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-010 | P0 | 按渠道定时查询模型输入价、输出价、缓存价、用户组倍率和 Key 倍率。 |
| FR-011 | P0 | 适配 NewAPI、Sub2API 及其二开差异；无法自动获取时允许人工维护，并标明数据来源。 |
| FR-012 | P0 | 每次价格确认形成不可覆盖的版本，记录币种、计费单位、来源、查询时间和生效时间。 |
| FR-013 | P0 | 每个请求关联其决策时采用的价格版本，确保历史成本可复算。 |
| FR-014 | P0 | 涨价经一次可信确认后限制新流量；降价须经再次确认或实际扣费验证后逐步增加流量。 |
| FR-015 | P0 | 价格过期或查询失败时，仅在能够形成保守费用上限的情况下继续参与调度；否则退出成本优选。 |
| FR-016 | P0 | 比较预估费用、实际扣费和余额变化；超过业务容差时标记计费异常并停止低价优选。 |
| FR-017 | P1 | 提供价格变化记录和影响范围，支持按模型、渠道和 Key 查询。 |
| FR-018 | P0 | 将不同币种和计费单位换算为统一比较单位，并记录汇率或换算规则的来源、生效时间和版本。 |
| FR-019 | P0 | 按账号、Key、模型和时间范围核对预估费用、上游账单及余额变化，无法归因的差额必须单独展示。 |

### 7.3 余额、额度与容量

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-020 | P0 | 查询并记录账号可用余额、Key 剩余额度及数据更新时间。 |
| FR-021 | P0 | 区分现金余额、预付额度、用户组额度、模型额度、日/月限额和额度重置时间。 |
| FR-022 | P0 | 识别多个 Key 共享同一账号余额的关系，不得重复计算可用余额。 |
| FR-023 | P0 | 为已发出但尚未结算的请求预留预计费用，完成后按实际费用修正。 |
| FR-024 | P0 | 按“确认余额－未结算预留－安全储备”计算可路由余额。 |
| FR-025 | P0 | 账号余额、Key 额度、模型额度或周期限额任一不足时，资源不得承接新请求。 |
| FR-026 | P0 | 余额查询失败时，使用最近可信余额扣除已知消耗形成保守下限；无法形成安全下限时停止新付费请求。 |
| FR-027 | P0 | 识别余额不足、额度耗尽和配额错误响应，并立即更新资源状态。 |
| FR-028 | P0 | 记录 RPM、TPM、并发、上下文和其他已知限制，并考虑进行中请求占用。 |
| FR-029 | P0 | 为稳定接管资源保留容量，测活不得占满全部快速资源。 |
| FR-030 | P1 | 根据近期消耗速度估算余额可持续时间；余额临界时先停止测活和高成本请求，再减少普通流量。 |
| FR-031 | P0 | 监控 Key 的启用状态、有效期和权限变化；Key 失效、被撤销或权限不足时立即停止新请求。 |
| FR-032 | P0 | 支持按租户和 SLA 等级设置容量使用上限与保留量，低等级流量和测活不得占用高等级服务的保留容量。 |

### 7.4 健康度与故障域

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-040 | P0 | 持续记录有效首字时间、完整时长、输出速度、完整成功、流中断、超时、限流和协议错误。 |
| FR-041 | P0 | 性能和稳定性按模型、上下文区间、请求类型、时段和路由资源分别统计。 |
| FR-042 | P0 | 使用近期 P50/P95/P99 和成功率评估资源，不能仅使用标称值或总体平均值。 |
| FR-043 | P0 | 样本过少或样本过期时标记为低可信度，不得作为稳定主渠道。 |
| FR-044 | P0 | 为资源登记官方供应商、代理层、账号、地区和网络等故障域；一个资源可属于多个故障域。 |
| FR-045 | P0 | 发现故障域集中异常时，同时限制相关资源；接管优先选择不同关键故障域。 |
| FR-046 | P0 | 健康状态至少包括未知、观察、可用、降级、冷却和停用。 |
| FR-047 | P1 | 资源恢复后先进入观察状态并逐步增加流量，避免短时波动引发集中迁移。 |

### 7.5 连续会话、缓存与成本调度

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-050 | P0 | 为连续会话记录每轮实际首字时间、累计首字时间和前缀平均值。 |
| FR-051 | P0 | 每轮结束都判断前缀平均首字时间是否达标，不以长会话最终平均值掩盖前几轮超标。 |
| FR-052 | P0 | 以近期高分位延迟和安全余量预测本轮风险；余额不足时优先选择快速稳定资源。 |
| FR-053 | P0 | 首轮、短会话、高优先级请求采用更保守的慢渠道准入条件。 |
| FR-054 | P0 | 缓存率按可缓存输入 Token 加权，天然不可缓存内容不计为未命中。 |
| FR-055 | P0 | 识别缓存绑定的渠道、账号、Key 和模型作用域，连续会话优先复用可延续缓存的资源。 |
| FR-056 | P0 | 预测资源切换后的缓存影响；预计低于目标时限制切换，除非更高等级 SLA 要求接管。 |
| FR-057 | P0 | 候选资源通过全部硬性条件后，按预计实际成功成本进行选择。 |
| FR-058 | P0 | 实际成功成本包含主请求、失败、缓存损失、重试、接管和未取消重复请求费用。 |
| FR-059 | P1 | 限制单次流量变化幅度，防止价格或健康状态波动造成渠道频繁切换。 |

### 7.6 真实业务测活

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-060 | P0 | 对长期无样本、样本过期或冷却结束的资源，允许使用少量真实业务请求测活，不依赖固定 `hello` 请求。 |
| FR-061 | P0 | 测活请求必须满足模型能力、数据许可、价格有效、余额充足、容量充足、会话可承受和接管资源可用。 |
| FR-062 | P0 | 敏感、高价值、不可重复副作用或业务明确禁止探索的请求不得参与测活。 |
| FR-063 | P0 | 分别限制全局、租户、用户、会话和资源的测活费用、次数、并发和错误预算。 |
| FR-064 | P0 | 试错机会依据样本陈旧程度、指标不确定性、潜在收益和失败历史分配，不能持续集中给同一用户或渠道。 |
| FR-065 | P0 | 测活失败、超时、费用异常或严重拖慢响应后进入冷却；连续失败应延长冷却时间。 |
| FR-066 | P0 | 再次测活必须同时满足冷却结束、价格和余额有效、探索预算恢复、会话预算充足及接管容量可用。 |
| FR-067 | P0 | 记录测活原因、决策快照、预算变化、首字、完整结果、缓存、费用和接管结果。 |
| FR-068 | P1 | 探索预算达到上限时暂停新测活，不影响正常稳定流量。 |

### 7.7 测活记账、接管与重试

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-070 | P0 | 分别维护用户体验账目、会话调度账目和全局探索账目。 |

## 8. 关键业务规则

### 8.1 会话延迟预算

```text
会话延迟余量 = 目标首字时间 × 已完成轮数 - 累计实际首字时间
```

- 快速请求形成余量，慢请求消耗余量。
- 选择慢渠道前必须保留安全余量，并使用近期高分位首字时间预测。
- 用户可能在任意一轮结束对话，因此每轮后的前缀平均值都必须受控。

### 8.2 缓存率

```text
缓存命中率 = 缓存命中的可缓存输入 Token ÷ 全部可缓存输入 Token
```

- 不按请求次数计算。
- 渠道切号或更换缓存作用域造成的损失必须计入。
- 当延迟目标和缓存目标冲突时，按业务配置的 SLA 优先级处理并记录原因。

### 8.3 可路由余额

```text
可路由余额 = 最近确认的可用余额 - 未结算请求预留费用 - 安全储备
```

- 账号余额和 Key 额度分别判断，任一不足都不可继续分配。
- 共享账号余额只计算一次。
- 余额数据过期时必须扣除已知消耗；无法得出安全下限时停止新请求。

### 8.4 实际成功成本

```text
实际成功成本 = 主请求费用 + 失败费用 + 重试费用 + 接管费用 + 未取消重复费用
```

- 成本比较以完整成功响应为单位。
- 官方标称倍率只作为输入，不能替代实际扣费。

### 8.5 价格变化

- 涨价：可信确认后立即限制新增流量。
- 降价：再次确认或用真实扣费验证后逐步增加流量。
- 查询失败：保留最后可信版本并降低新鲜度；不能形成保守价格时退出成本优选。
- 扣费异常：停止低价优选，待价格和账单重新确认后恢复。

### 8.6 测活再次准入

```text
冷却结束
且价格与余额有效
且探索预算充足
且会话能够承受
且稳定资源保有接管容量
```

任何一项不满足，均不得再次测活。

## 9. 状态定义

### 9.1 健康状态

| 状态 | 可执行动作 |
| --- | --- |
| 未知 | 不作为稳定资源，仅等待资料完善或进入观察。 |
| 观察 | 仅允许受限测活。 |
| 可用 | 可参加正常调度。 |
| 降级 | 限制流量，不作为优先接管资源。 |
| 冷却 | 禁止测活和正常新增流量，等待条件恢复。 |
| 停用 | 禁止新增请求，仅保留历史和审计。 |

### 9.2 余额状态

| 状态 | 处理要求 |
| --- | --- |
| 正常 | 正常参与调度。 |
| 临界 | 停止测活和高成本请求，减少普通流量。 |
| 未知 | 使用保守下限；无法确认安全余额时停止新请求。 |
| 耗尽 | 立即停止新增请求。 |
| 异常 | 停止成本优选并等待人工或自动复核。 |

## 10. 异常处置矩阵

| 异常 | 默认处理 | 恢复条件 |
| --- | --- | --- |
| 价格上涨 | 限制新增流量，更新成本预测 | 新价格确认完成 |
| 价格下降 | 保持原流量，不立即迁移 | 再次确认或实际扣费验证 |
| 价格数据过期 | 使用保守价格；无法估计则退出成本优选 | 获取可信价格 |
| 余额临界 | 停止测活和高成本请求，逐步减少流量 | 可持续时间恢复到安全范围 |
| Key 额度耗尽 | 立即停止该 Key 新请求 | 额度重置或人工恢复 |
| Key 失效或权限不足 | 立即停止该 Key 新请求并告警 | Key 状态与目标模型权限重新验证通过 |
| 实际扣费异常 | 停止低价优选，保留必要 SLA 流量或直接停用 | 价格与扣费复核通过 |
| 首字持续变慢 | 降低流量并消耗错误预算 | 观察期内性能恢复 |
| 首字后中断 | 记为完整失败，不拼接其他模型输出 | 后续请求重新选择资源 |
| 测活超时 | 首字前由稳定资源接管，测活资源进入冷却 | 冷却、预算和容量均恢复 |
| 同故障域集中失败 | 同时限制相关资源 | 故障域恢复并通过观察 |
| 模型或能力不符 | 立即排除该资源 | 能力重新验证通过 |
| 全部合规资源不可用 | 返回明确不可用结果并告警 | 至少一个合规资源恢复 |

## 11. 默认产品策略

| 项目 | 默认值 |
| --- | --- |
| 连续会话首字目标 | 前缀平均不超过 10 秒 |
| 缓存目标 | 可缓存输入 Token 命中率不低于 90% |
| SLA 业务测活记账 | 严格补偿模式 |
| 测活费用 | 计入独立探索预算和实际成功成本 |
| 接管边界 | 仅在有效首字输出前允许无感接管 |
| 模型替换 | 未经授权禁止自动替换或降级 |
| 价格处理 | 涨价快速限制，降价确认后逐步增加流量 |
| 未知状态 | 按保守策略处理 |
| 不可测活请求 | 敏感、高价值、不可重复副作用和业务明确禁止的请求 |

## 12. 验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 配置 20 个渠道及其账号、Key、模型和故障域 | 可完整查询每个路由资源的身份、能力、状态和关系。 |
| AC-02 | 某渠道模型价格上涨 | 新请求按新价格重新判断；历史请求仍按原版本复算。 |
| AC-03 | 某渠道价格下降但尚未验证 | 不立即集中迁移；验证后才逐步增加流量。 |
| AC-04 | 多个 Key 共享账号余额且存在并发请求 | 余额不重复计算，进行中费用被预留，不发生可预见超支。 |
| AC-05 | 账号有余额但目标 Key 日额度耗尽 | 该 Key 被排除，其他合格资源仍可参与调度。 |
| AC-06 | A 渠道约 20 秒且低价，B 渠道约 3 秒且较贵 | 系统根据会话前缀平均值和安全余量分配，预算不足时使用 B 恢复。 |
| AC-07 | 切换低价渠道会使缓存率低于目标 | 系统限制切换，或因更高优先级 SLA 切换并记录原因。 |
| AC-08 | 低权重渠道长期无样本 | 仅在模型、数据、余额、预算和接管条件均满足时获得有限测活。 |
| AC-09 | 测活渠道首字超时 | 稳定资源在首字前接管；延迟计入 SLA，费用计入探索预算和实际成本。 |
| AC-10 | 测活渠道失败或费用超标 | 进入冷却；仅在冷却结束且预算充足时再次获得机会。 |
| AC-11 | 多个渠道实际共享同一官方上游并同时故障 | 系统识别共同故障，不在相关资源之间反复接管。 |
| AC-12 | 已输出首字后发生流中断 | 记为完整失败，不拼接另一模型内容。 |
| AC-13 | 请求包含不可重复的外部写入操作 | 不自动并发测活或盲目重试。 |
| AC-14 | 渠道不满足租户数据许可但价格最低 | 在价格比较前被排除。 |
| AC-15 | 全部合规资源不可用 | 返回明确不可用结果，不自动降级模型或使用不合规渠道。 |
| AC-16 | 查询任一历史请求 | 可看到当时的候选、排除原因、价格、余额、选择、延迟、费用和接管记录。 |
| AC-17 | 两个渠道使用不同币种或计费单位 | 系统使用带版本的统一换算值比较成本，历史结果可按当时规则复算。 |
| AC-18 | 单一租户流量突增或测活并发上升 | 不占用高 SLA 业务的保留容量，受限流量按已配置规则处理。 |
| AC-19 | 余额耗尽、Key 失效或错误预算快速消耗 | 立即产生包含影响范围和处置建议的告警，并持续记录到恢复关闭。 |
