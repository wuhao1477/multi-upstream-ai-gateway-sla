## A. 需拍板的决策（6 项）

### A1. "一期单级 SLA"的语义必须落地（影响最大，卡 M0 种子与 M2/M4 验收）

**问题**：[15 §2.1 S3](../dev/15-scope-and-preflight.md) 定"一期只实现单级，表结构预留多级"，但一期范围内大量规则依赖等级差异，单级下无法求值：

- canary 准入第 1 条："仅**铜级或无 SLA 承诺**的别名参与，金/银**永不**参与"（[05 §2.0](../dev/05-scheduling-and-operations.md)）；[AC-08](../dev/14-acceptance-matrix.md) ③ 要求"金/银别名请求一次都不得落到 canary binding"。
- [AC-06](../dev/14-acceptance-matrix.md) 用"金级别名"验证接管；每跳期限公式引用"金级单跳 P95≤5s"。
- 容量保留："金级 20%、接管保留＝金级峰值并发 10%"（[05 §4.2](../dev/05-scheduling-and-operations.md)）。
- 全渠道不可用排队："金 15s / 银 5s / 铜 0s"（[05 §3.2](../dev/05-scheduling-and-operations.md)）。
- [00 M0 种子](../dev/00-overview-and-milestones.md)：3 个别名各映射一条 `routing_policies`，却只有"一行 `sla_targets`"——3 条策略与 1 行目标如何对应未说明。

**推荐方案**："单级"重新表述为"**单一承诺等级**"：

1. 金/银/铜三条 `routing_policies` 模板照常入 M0 种子，但**对外只承诺一档 SLA 数值**（`sla_targets` 只配一档）。
2. **调度与 canary 判断一律读策略行的显式字段，不读等级名**：`routing_policies` 新增 `canary_eligible BOOLEAN`（默认仅"无承诺"策略为 true）、`is_committed BOOLEAN`（容量保留/接管保留只对 committed 策略生效）；排队时长沿用已有 `no_resource_wait_ms`。
3. AC-06/08 的判定措辞由"金级/铜级"改为"committed / canary_eligible 别名"。

二期加等级只是多插策略行，零改结构。

**影响面**：02（`routing_policies` 加两列）、05 §2.0/§3.2/§4.2、14 AC-06/08 措辞、PRD §2.1 补一句话。

### A2. `/v1/models` 透传与"别名即策略载体"互相打架（主力客户端接入第一步就会撞上）

**问题**：FR-062/117 规定对外模型名是**别名**（如 `gpt-5.5-sla-1`，上游不存在）；[03 §4 约束 4](../dev/03-upstream-layer.md) 又要求 `GET /v1/models` **全量透传上游模型目录**（Codex 靠它刷新模型列表）。二者不可同时成立：

- 透传 → Codex 看到并使用**上游真实模型名**发请求，绕过全部别名策略（SLA 等级、测活资格、配额），FR-117 形同虚设。
- 不透传 → 违反 03 §4；且 `Models(ctx, b Binding)` 该选哪个 binding 的目录也从未定义（20 个渠道目录各不相同）。

**推荐方案**：`/v1/models` **由网关合成，不透传**：

1. 返回该凭证 `allowed_aliases` 范围内的启用别名列表（OpenAI models 响应格式），`x-models-etag` 由我方按别名表版本生成。
2. 请求的 model 不在别名表 → **404**；在表但不在该凭证 `allowed_aliases` → **403**（与 AC-33 越权口径一致）。
3. 上游 `Models()` 保留，但降级为**协议能力探测与管理面用途**，不对外暴露。

**理由**：字节透传硬约束保护的是**响应流保真**（SSE 事件生命周期，三项目翻车处），models 目录是控制面元数据，合成不触碰 Codex 的 SSE 严格性；而透传真实名会让策略体系整体失效。

**影响面**：03 §2/§4、13 §1.3 注记、14 补一条 M1 判定（非别名模型名 404）。

### A3. 缓存目标默认值三处口径不一致

**问题**：[PRD §11](../PRD.md)"缓存目标：命中率不低于 **90%**（对金、银级承诺）" vs [PRD §2.1](../PRD.md)"一期**不承诺**（仅做会话粘性，**无目标约束**）" vs [02 §6quater](../dev/02-data-model.md) FR-056 切换抑制默认目标 **0.6**。"无目标约束"与"FR-056 拉入一期（低于目标则限制切换）"字面矛盾。

**推荐方案**：拆成两个概念，分别定值：

1. **对外承诺**：一期无（§2.1 为准；≥90% 推二期）。
2. **内部切换抑制目标**（FR-056 用）：`config_params` 默认 **0.6**，长会话实测后调整。
3. PRD §11 该行改为："缓存切换抑制目标（内部参数，非对外承诺）：默认 0.6 可配；≥90% 承诺二期兑现"。

**影响面**：仅 PRD §11 措辞；02 §6quater 已按 0.6 设计，不动。

### A4. 主动测活已实质改为"运维预置模板"，需修订 FR-060

**问题**：FR-060 原文"使用少量**真实业务请求**测活，不依赖固定 hello 请求"。但 FR-112 不存正文 → 无业务流量时段（主动测活的主场景）**没有任何正文可复用**。[02 §6ter](../dev/02-data-model.md) 已按 `probe_templates`（运维编写探测请求体）设计，这是对 FR-060 字面语义的实质偏离，且模板保真度低于真实请求（文档已明示该代价）。

**推荐方案**：PRD v1.4 修订 FR-060 为："测活请求使用**贴近真实工作负载的预置模板**（多轮上下文、工具定义、典型长度，运维维护，按模型×协议配置），不得使用空洞短请求（hello/ping 类）；存在业务流量时优先走 canary（FR-121），不发模板探测。"

**影响面**：PRD FR-060；02 §6ter 已是该设计，不动。

### A5. canary 小时上限口径：每"渠道"还是每"binding"

**问题**：FR-121 写"**每渠道**每小时次数上限"；实现（[02 §6](../dev/02-data-model.md) `resource_health` / [05 §2.0](../dev/05-scheduling-and-operations.md)）按 **binding**（渠道×账号×Key×模型）执行 `canary_max_per_hour=20`。一个渠道挂 N 个 Key/模型时，渠道级实际上限是 20×N，与 FR 字面不符，影响 AC-08 判定。

**推荐方案**：口径定为 **per-binding**（维持实现现状），FR-121 措辞改"每路由资源（binding）每小时"。理由：canary 验证的对象就是 binding 粒度的健康度；渠道级聚合计数徒增一套跨 binding 原子机制而无对应收益。若担心多 Key 渠道放量过大，二期再加渠道级总闸（默认不启用）。

**影响面**：PRD FR-121 措辞、14 AC-08 判定语言。

## B. 设计缺口（7 项，已附推荐补法，认可即执行）

### B7. 主动测活请求无入站凭证可记账
`requests.gateway_client_id` 为 `NOT NULL`（[02 §4.1](../dev/02-data-model.md)），但主动测活由 steward 内部发起，没有调用方凭证，账本插不进去。
**推荐**：预置内置凭证 `system-probe`（迁移种子创建；`status` 特殊标记不可用于外部调用；`quota_daily_usd=NULL`）。探测请求挂它记账；费用由五维探索预算（`probe_budget_windows`）约束，**不占任何真实调用方日配额**；FR-072"计入实际成功成本"照常成立。

### B8. FR-004/FR-095 五层停用开关在数据模型不完整
仅 `channels` 有 `status/disabled_reason/disabled_until`；`upstream_accounts` 无任何状态列、`fault_domains` 无停用载体、`bindings` 无开关。"账号级/故障域级立即停用+原因+有效期"（FR-095）无表可落。
**推荐**：02 补三处——`upstream_accounts` 加 `status/disabled_reason/disabled_until`；`bindings` 加 `enabled BOOLEAN NOT NULL DEFAULT true`；`fault_domains` 加 `disabled_until/disabled_reason`（域停用＝selector 排除该域全部 binding）。M1 建表一步到位，selector 过滤序 4 前追加"人工停用"判据。

### B9. 容量保留无跨实例执行载体 + 05 引用的 §4.3 不存在
FR-028/029/032（进行中请求占用、接管保留、金级保留、测活≤5%）都需要跨实例一致的并发计数；canary 有 DB claim，普通容量只有内存快照，双实例必然超卖。[05 §1.1](../dev/05-scheduling-and-operations.md) 过滤序 7 引用的"§4.3"在文中不存在（实际是 §4.2 且只有保留比例、没有判定规则）；渠道容量**基数**（RPM/并发上限）从哪来也未定义。
**推荐**（一期降精度不降语义，明示）：
1. 容量基数＝渠道/Key 登记的 RPM 与并发上限（`/admin/bindings` 录入 + 采集器能采到的 `RateLimit` 自动回填）；**未登记容量的渠道不启用任何保留**（无基数即无从保留）。
2. 执行层：仅对"启用保留"的渠道用与 canary 同构的 DB 原子计数；普通渠道不设闸（避免每请求一次 DB 往返破坏 P99≤50ms）。
3. 05 补 §4.3 写清判定规则与"未登记＝不保留"的降级说明。

### B10. FR-016 计费异常与 FR-019 对账展示无载体
`cost_variance` 列已建，但"超容差→标记计费异常→停止低价优选→复核后恢复"没有阈值、触发与恢复流程；FR-019"按账号/Key/模型/时间核对、无法归因差额单独展示"没有任何端点。两条都是 P0。
**推荐**：M3 一并交付——
1. 容差默认 **5%**（`config_params` 可配，关键项）；滚动窗口内 `|cost_variance|/estimated_cost` 超容差的 binding → `alert_events(category='billing_anomaly', P2)` + 该 binding 退出低价优选（`decision_snapshot` 记原因）；恢复＝人工确认或连续 N 次（默认 20）一致。
2. 新增 `GET /admin/ledger/reconciliation?scope=account|key|model&from=&to=`：聚合预估 vs 实扣 vs 余额变化，差额不可归因部分单列 `unattributed`。

### B11. 自监控指标无暴露方案
[06 §6](../dev/06-deployment-and-operations.md) 列了十余项必须监控的指标（决策开销 P99、PG 提交延迟、连接池耗尽、outbox 积压、取消成本占比、`downstream_ttft_delay_ms` 等），但 compose 无任何指标组件，"自监控"无处可看；M4 压测判定要靠这些数。
**推荐**：sla-core 暴露 **Prometheus 文本端点 `/metrics`**（仅内网监听，与 `/admin` 同边界）；`deploy/` 附可选 `prometheus`（+grafana）compose profile，默认不启动；不自建面板。M4 压测以 `/metrics` 出数。

### B12. AC-19 与告警落库的里程碑时序错位
[14 §1](../dev/14-acceptance-matrix.md) 把 AC-19（余额耗尽/Key 失效/错误预算告警）验收在 **M3**；[00 M4](../dev/00-overview-and-milestones.md) 交付物才含"告警 P1～P3（落库）"。
**推荐**：`alert_events` 写入路径（含 `dedup_key` 同因合并、生命周期行锁）**提前到 M3** 交付，覆盖余额/Key/价格/采集类告警；M4 只补经营闭环类（错误预算消耗、容量趋紧、canary 相关）。00/14 对应行同步。

### B13. 测活预算"用户"维度无身份定义 + `/admin` 内网边界未落地
FR-063 五维含"用户"，`probe_budget_windows.scope_kind` 有 `'user'`，但系统内只有 gateway_client / tenant / session，无 user 概念。另外 [09 §1](../dev/09-admin-api.md)"管理平面只在内网/本机可达"没有对应的部署配置。
**推荐**：一期 **user ≡ gateway_client**（个人/内部场景一人一凭证成立），`scope_id` 填 client id，PRD 术语表加一行；`deploy/Caddyfile` 明确**不代理 `/admin/*` 与 `/metrics`**（仅容器网络/本机可达），06 §1 补一句。
