# 渠道详情、备份导入与中文展示设计

**日期：** 2026-09-11  
**状态：** 待用户确认

## 目标

修正管理界面的层级关系；让 all-api-hub 导入后的渠道、账号、凭证和上游 Key 都能在对应管理页看到；Key 自动获取失败时不影响渠道与账号导入；前端所有后端枚举都通过中文文案展示。

## 当前问题

1. `web/src/router/panes.ts` 将 `detail` 与一级菜单共用 `PANES` 和 `PANE_ORDER`，`/detail` 还是独立顶层路由。详情依赖 Pinia 的 `currentID`，路由本身不携带渠道 ID。
2. `internal/admin/import_api.go` 的导入事务只建立渠道、探测快照、账号和采集凭证，没有读取上游 Key 的步骤。
3. 导入页面只刷新渠道 store，没有刷新账号/Key/凭证 store。后端已经写入的账号在当前页面缓存中不可见。
4. 导入结果、站型、采集能力、支持级别、凭证类型和部分状态直接渲染英文枚举值。

## 设计

### 1. 路由与布局

- `PANES` 只描述一级菜单：渠道、账号、Key、采集凭证、批量导入。
- 渠道详情使用 `/channels/:id`，路由名为 `channel-detail`，从渠道列表、账号列表和 Key 列表进入。
- 旧 `/detail` 保留为重定向到渠道列表；不再出现在左侧菜单，也不再出现在 `NavIcon` 的一级菜单类型中。
- 详情页从路由参数读取渠道 ID，并等待渠道列表加载后选择渠道。Pinia 的 `currentID` 只作为当前页面数据缓存，不再作为详情入口的唯一来源。
- 详情路由通过 `meta.parent = 'channels'` 让侧栏继续高亮“渠道管理”；顶栏从路由元信息读取“渠道详情”标题和说明。

### 2. all-api-hub 导入与 Key 自动登记

导入顺序保持为：公开探测 → 渠道/探测快照/账号/凭证事务提交 → 使用已登记凭证完成会话鉴权 → 读取 Key 列表 → 逐把取得 Key 明文并登记。

- 新增采集器可选能力 `KeySecretResolver`，不改变已有 `Adapter` 接口。NewAPI 使用 `POST /api/token/{id}/key`；Sub2API 使用 `GET /api/v1/keys/{id}`。只在服务端内存中短暂持有明文，然后交给现有 `store.CreateKey`；管理接口与日志继续只返回前缀。
- 复用现有 `Authenticate` 和 `Session`。Key 列表仍由现有 `FetchKeys` 提供，Key 明文由站型解析器按上游标识取得。
- 以 `(account_id, external_ref)` 识别已导入 Key。已存在的 Key 不重复创建，并可用本次读取到的配额/有效期/分组信息更新现有行；新 Key 才需要读取明文。
- Key 导入在渠道基础事务提交之后执行，不把上游网络请求放入渠道事务。会话鉴权、Key 列表读取、单把明文读取和单把写入失败都记录为该条目的中文提醒，渠道、账号和凭证仍保持已导入。
- 导入结果新增 `keys_found`、`keys_imported`、`keys_skipped`、`keys_failed` 汇总及逐条字段。Key 获取失败不把条目状态改成 `failed`，提醒放入 `warning`。
- 试运行不访问需要鉴权的 Key 接口，也不写 Key；只保留当前站点可导入的判断。
- all-api-hub 备份中的账号、访问令牌仍按现有字段读取。空的 `channelConfigs`、`apiCredentialProfiles` 和标签区不虚构为本项目的渠道或 Key 数据。

### 3. 前端缓存与中文文案

- 正式导入成功后同时刷新 `channels`、`resources` 和 `credentials` store，确保三个一级管理页立即可见。
- 在 `web/src/utils/format.ts` 集中提供中文展示函数，至少覆盖：站型、能力、支持级别、同步状态、导入状态、渠道/账号/Key/凭证状态、凭证类型、异常类型和计价口径。
- 模板保留原始枚举值用于 `data-*` 选择器和逻辑判断，但所有可见文本使用映射函数。未知值显示“未知站型”“未知状态”等中文，不直接回显英文枚举。
- 限流展示将 `rpm` 转为“次/分钟”；`per_token` 等计价口径使用中文描述。

## 错误处理与安全边界

- Key 自动登记失败只影响 Key 部分，不回滚已提交的渠道、账号和凭证。
- Key 明文不进入 `HubImportResult`、HTTP 响应、日志、错误文本或前端状态；只传给现有创建函数。
- 上游返回空 Key、掩码 Key、无效 Key 标识或解析器未实现时，计入 `keys_failed` 并给出不含明文的提醒。
- 重复导入不重复创建渠道或 Key；已有渠道的补齐逻辑和现有事务原子性保持不变。

## 验收与测试

- Go：验证 NewAPI/Sub2API Key 明文解析、Session 请求路径、导入后新增 Key、重复 Key 不重复、Key 失败不影响渠道/账号/凭证、结果计数和 warning。
- 前端：验证详情不出现在一级菜单、`/channels/:id` 可直接打开且侧栏高亮渠道管理、列表入口使用新路由、导入后刷新三个 store、中文映射覆盖可见枚举。
- 运行 `pnpm test`、`pnpm run build`、相关 Go 测试，并运行现有 UI/SPA 验收脚本。
