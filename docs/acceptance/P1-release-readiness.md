## 3. 必须一起发的五条已知缺口

发版不等于没缺口，等于**缺口都被写下来且都不致命**。逐条给出"为什么不阻断发版"。

### 3.1 AC-38 的"两族都跑过"证据只剩首轮，且今后不会再有新的

> **2026-08-31 这条缺口升级了，随即按"认首轮归档为终局证据"结清。**
> 放弃那 20 个站时，三类"需人工"恰好装满了**全部 13 个 sub2api 渠道**，
> 于是真库里 sub2api 的在纳管渠道数为 **0**：判定基准（每个已注册家族都跑过）
> 与真库现状不可能同时满足，本条从此**不可复验**。
>
> 处置：**判定基准一个字不动**，AC-38 保持 ⚠️ 并注明 sub2api 侧证据取自
> 2026-08-29 那份归档。另两条出路（改判定基准 / 留一个注定失败的标本）
> 分别被 [14 §3](../dev/14-acceptance-matrix.md) 规则 3 和「只保留可用的」
> 这个决定排除，排除依据逐条写在
> [P1-evidence AC-38 那段 ⚠️](P1-evidence.md#ac-38-逐家族手动刷新逐项结果与-unsupported-显式上报)。
> 将来接入任一 sub2api 站点，本条自动重新可验。

2026-08-30 复测时 13 条 sub2api **全部 401**，`matrix` 里 `sub2api|*` 六项一条不剩
（[§2.1bis](P1-evidence.md#21bis-次轮复测sub2api-掉到-0-可用ac-38-的两族都有真实结果只对首轮成立)）。

**不阻断**：退的是别人家站点的凭证有效期，不是代码 —— 两轮之间 `internal/collector`
只有一处改动（加 `TokenExpiryFrom`），它不会让原本能过的站变 401。判定基准
（`collector.All()` 每族都跑过）在首轮那份归档里成立，且该基准本身有单测守着。
**但要接受**：今天重跑，sub2api 侧拿不到新证据。

2026-08-31 复评补了一条**旁证**（不是这条缺口的解）：`97a8caa` 之后在 HEAD 上重跑
58 项，newapi 系那条采集路径六项仍全绿（`account`/`groups`/`keys`/`model_catalog` ok +
`subscription_quotas` unsupported + 限流 429）。所以「改采集代码把站弄坏了」这个
可能性被排除了；sub2api 那 13 条仍是凭证到期，不是代码。

### 3.2 ~~那 20 个站里 11 条永远不会自愈~~ → 已按"放弃纳管"结清（2026-08-31）

> 这条不再是缺口：20 个站已全部停用，不在纳管范围内。保留标题是因为下面那段
> 说明了"为什么修复不会让它们好起来"，而那正是放弃它们的依据。

`RefreshLead` 自锁修好之后（[§5.15](P1-evidence.md#515-主动续期从来没有触发过本轮发现的真缺陷已修)），
11 条 sub2api 报 `无 refresh_token 可用（需人工重登）`。库里 0 个 refresh_token、
0 个 password，**修复不会让它们好起来** —— 改善只在于失败从静默变成具名。

**不阻断**：P1 不转发请求，采不到的渠道只是台账缺行，不影响任何在线路径。
恢复路径存在且有断言（04 §5.3 账密重登）。

### 3.3 `billing_unit`：~~权威表的列定义本身是反的~~ → 已修；仍欠 P3 那条计算断言

⚠️ 2026-08-31 复评发现问题不在 CI 而在**表定义**：`price_versions.billing_unit` 是
`NOT NULL DEFAULT 'per_1m_token'` **且无 CHECK**，而目录表可空 + 有 CHECK ——
**不设防的那张恰是 P3 要读的权威表**。015 想禁止"把未声明伪装成按 token 计价"，
006 的列定义强迫写入路径这么做。

**已于 2026-08-29 修**：迁移 018 去掉默认值与 `NOT NULL`、补一条与目录表取值逐字相同的
CHECK，`sink.go` 的 `COALESCE` 换回 `NULLIF`；守卫落在 `test-migrate.sh` 7/7
（断言"两处列定义相等"，另有真写入探针），反向自验 6 路全红。实库已应用（`applied=1`，
`price_versions` 仍 0 行，改表零风险）。详见
[§3.2bis](P1-evidence.md#32bis-两张表对同一个口径的处置相反而不设防的那张是权威表2026-08-31-查明2026-08-29-已修)。

**仍要一起发的部分**：成本公式那条 CI 断言（单价 3.0 / `per_1m_token` / 1000 token
→ 0.003）**依然没有** —— P1 无成本计算代码，写出来只能是"测试自己算一遍除法"。
且 02 §3 的 `unit_tokens` 只定义了三种按 token 的口径，而 `per_call` 实测占 15%、
NULL 也合法；两支公式已写进 02 §3，P3 实现时不得只照那个除法写。
记账从 #7/#9（均已关闭，那句"勿让 issue 关闭时漏掉"已空放过一次）移到 `gate.yml` 注释。

### 3.4 真库里有一行夹具残留，3 条 Key 断言跑在它身上（已停用+改名，仍是夹具）

`channel 1` 现名 `【夹具·勿删】verify-ui 残留（FR-094 真库靶子）`，`status=disabled`
且带停用原因；base_url 仍指向已删除的 mock 端口。**真渠道采到的 Key 数为 0，且是恒为 0**

**不阻断**：那 3 条验的是**渲染层不吐明文**，与 Key 从哪来无关，断言本身有效。
**但要接受**：它们不是"真采集的 Key 也不回显"的证据，改名只是让这行自报身份。
真库仍是 64 真 + 1 夹具。
