# 安全债登记

日期：2026-10-09。来源：[Issue #30](https://github.com/wuhao1477/multi-upstream-ai-gateway-sla/issues/30)。
本文件登记后续工作，不授权生产迁移、秘密轮换或历史清理。

## D1：非 Cookie 凭证明文存储

**状态：代码已实施（2026-10-10，#34）；生产库迁移待维护窗口执行。**

实施要点：迁移 034 加密文列；035 在同一事务里先由 Go 回填并逐行解密比对，再删除明文列，
缺密钥或比对失败即整体回滚（`internal/store/credential_migration.go`）。密文格式与 AAD 见
`internal/store/credential_cipher.go`；WebDAV 地址的展示值与编辑约定见 09 的 `/admin/hub-sync`。
生产升级顺序见 06 顶部说明。下文为当时登记的方案与验收标准，保留作对照。

尚未实施：密钥轮换（密文已带密钥版本，届时按版本选密钥）；旧明文备份、WAL 与日志的清理。

### 秘密范围

| 位置 | 需要保护的内容 |
| --- | --- |
| `upstream_keys.secret` | 上游 Key 明文 |
| `collector_credentials.access_token` | 采集访问令牌 |
| `collector_credentials.refresh_token` | 可轮换的刷新令牌 |
| `hub_sync_config.webdav_password` | WebDAV 密码 |
| `hub_sync_config.backup_password` | 备份解密密码 |
| `hub_sync_config.webdav_url` | URL 中承载认证的 query 参数、userinfo 等秘密；不能只迁移密码列而遗漏 URL |

盘点还应覆盖导入、手动编辑、定时同步、刷新和读取路径。带认证信息的 WebDAV URL 应整体
加密保存，管理面改为非秘密展示值与存在性信息；具体编辑契约在迁移任务中确认，不能继续
将认证参数当作普通地址回显。已经加密的 Cookie 不属于待回填范围。

### 目标实现

- 复用现有 AES-GCM 实现，提取不依赖存储表的加密组件。Cookie 继续使用现有
  `SLA_COOKIE_SECRET_KEY`、AAD 和密文格式，不借此次提取改变已存 Cookie。
- 其他凭证使用独立部署密钥 `SLA_CREDENTIAL_SECRET_KEY`，要求 Base64 编码的
  32 字节随机密钥；不得从 `ADMIN_TOKEN` 派生，不写入数据库、仓库或公开 CI。
- 新密文携带格式版本、密钥版本及随机 nonce；每次写入生成新 nonce。AAD 绑定
  表名、稳定记录 ID、字段名，拒绝跨账号、跨记录、跨字段替换密文。
- 密钥缺失、错误、版本未知或密文被篡改时明确失败；不退回明文读取或写入。
  错误只能携带记录定位信息与安全类别，不能输出密钥、明文或密文内容。
- 写入与刷新保留现有事务、账号级刷新锁和顺序：上游轮换成功后，必须先成功
  持久化新 access/refresh token，再释放锁；加密不引入异步写入窗口。

### 必须同时修改的 SQL 与读写语义

- `left(secret,8)` 不能作用于密文。由 Go 在秘密写入时计算独立的 `secret_prefix`，
  与密文在同一事务更新；列表只读取前缀，不批量解密完整 Key。
- `CredentialTokenDiffers` 不再以 SQL 比较明文：读取并解密后比较，继续区分
  “没有凭证”与“凭证未变化”，解密失败不能被解释为未配置。
- 明确处理 NULL、空值保留、`has_*`/凭证存在性查询、密码留空不改，以及创建、更新、
  导入修复和刷新等全部写路径；不能因换列而清空未提交修改的秘密。
- 加密所需记录 ID 在当前事务内确定。业务事务失败时，密文、前缀和其他字段一起回滚。

### 迁移与恢复前提

1. 获得独立授权并确定维护窗口，停止全部会读取、写入或刷新这些凭证的 core/collector
   实例，防止迁移期间旧进程继续写明文或轮换 refresh token。
2. 在受控位置创建备份并实际验证可恢复；记录与备份对应的密钥版本，先验证新密钥
   在全部目标实例可用，再进行迁移。不得将生产备份作为测试夹具提交。
3. 在事务内回填新密文与前缀；全量验证每个值可解密并与原值一致，再抽样核验实际业务
   路径。验证失败则回滚本次事务，不启动混用新旧格式的服务。
4. 完成核验后才能移除旧明文列并切换新版本；不长期维护明文兼容读取。重启写入实例
   前确认读写代码、格式版本及密钥部署一致。
5. 恢复演练必须同时恢复数据库和对应密钥版本，验证创建、读取、刷新与重启。
   已发生上游令牌轮换时，单独恢复旧数据库可能恢复已失效的 refresh token，须在维护
   方案中确认重新登记步骤，不能承诺仅回退数据库就能恢复采集。
6. 旧备份、WAL、历史日志中的明文不会随新列加密而消失。其保留、销毁与必要的凭证轮换
   需另行盘点、授权；本轮不删除历史数据，也不改写 Git 历史。

### 独立迁移验收标准

- 指定秘密列不再包含合成明文标记；同一秘密重复加密的密文不同。
- 跨记录、跨字段 AAD 替换以及错误密钥、缺失密钥、篡改密文均明确失败。
- 创建、读取、编辑、导入、refresh token 轮换、进程重启、备份恢复全链路在真实
  PostgreSQL 通过；刷新锁与持久化顺序不变。
- 前缀列表不需要解密完整列表，API、日志、同步历史和错误均无完整秘密。
- 旧明文列已经移除；恢复操作具备匹配的密钥版本，不依赖明文兼容分支。

**登记完成不等于加密完成。** 此处不新增迁移文件或加密运行时配置。
