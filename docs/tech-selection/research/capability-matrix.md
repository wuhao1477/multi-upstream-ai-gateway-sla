# PRD 能力覆盖矩阵

## 1. 判定方式

矩阵先判断 stock 项目是否有对应产品语义，再判断缺口能否按既定侵入等级补充：

| 标记 | 含义 |
| --- | --- |
| 原生 | 固定提交已具备主要语义，但仍需生产验证 |
| L0 外置 | 不改项目源码，由外部控制组件通过 API、Profile 或标准协议完成 |
| L1 扩展 | 使用项目正式插件或策略接口 |
| L2 小改 | 修改单一稳定边界 |
| L3 核心改造 | 修改请求链路及多个状态模块，不接受 |
| 阻断 | 许可证或授权条件不满足 |

“L0 外置”只表示不修改上游源码，不表示定制工作量很小。对本项目而言，SLA 控制组件本身仍是核心产品能力。

## 4. 三项容易误判的能力

### Webhook

AxonHub 的 Webhook 是渠道自动停用后的异步通知，不能在请求前返回渠道选择。OmniRoute 的 Webhook 事件更多，也仍属于异步结果和告警集成；请求前控制依赖其 Middleware/Plugin。

### 自动回退

AxonHub、两个 Octopus、Aether、OmniRoute 和 ccLoad 均有不同程度的首内容前串行回退，但没有候选原生满足“根据会话剩余 TTFT 预算动态启动稳定资源、核对取消、记录继续计费和全部重复费用”。

### 价格和余额

能够展示静态模型单价、Token 成本或 Provider 额度，不等于满足 FR-010～032。全部候选都缺少完整的 NewAPI/Sub2API 价格可信确认、共享账号余额、费用预留、保守余额和账单差异处理。

## 5. 矩阵结论

没有任何候选可以直接满足 PRD。AxonHub 的优势不是原生覆盖最多，而是许可证相对可控、数据面边界清晰，并能通过单资源 Profile 把缺失的 SLA 语义整体放在外部控制组件中，避免长期修改上游核心。
