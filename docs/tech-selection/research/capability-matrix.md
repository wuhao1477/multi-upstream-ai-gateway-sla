# PRD 能力覆盖矩阵

## 1. 判定方式

矩阵先判断 stock 项目是否有对应产品语义，再判断缺口能否按既定侵入等级补充：

| 标记 | 含义 |
| --- | --- |
| 原生 | 固定提交已具备主要语义，但仍需生产验证 |
| L0 外置 | 不改项目源码，由外部控制组件通过 API、Profile 或标准协议完成 |
| L1 扩展 | 使用项目正式插件或策略接口 |
| L2 小改 | 修改单一稳定边界 |
| L3 核心改造 | 修改请求链路及多个状态模块，不接受 |
| 阻断 | 关键执行能力缺失，采用接近重写 |

“L0 外置”只表示不修改上游源码，不表示定制工作量很小。对本项目而言，SLA 控制组件本身仍是核心产品能力。

## 4. 四项容易误判的能力

### Webhook

AxonHub 的 Webhook 是渠道自动停用后的异步通知，不能在请求前返回渠道选择。OmniRoute 的 Webhook 事件更多，也仍属于异步结果和告警集成；请求前控制依赖其 Middleware/Plugin。

### 自动回退

AxonHub、两个 Octopus、OmniRoute 和 ccLoad 都有某种流式预读或串行回退，但其提交信号可能只是解析事件、role、lifecycle 或其他元数据，不等于用户可见内容；Aether 和 NewAPI 的普通流式路径也不能普遍保证提交前切换，Sub2API 的首语义输出保护主要覆盖 OpenAI 路径。没有候选原生满足“根据会话剩余 TTFT 预算动态接管、核对取消、记录继续计费和全部重复费用”。

### 价格和余额

能够展示静态模型单价、Token 成本或 Provider 额度，不等于满足 FR-010～039。NewAPI 的模型/分组倍率主要服务内部扣费，Sub2API 的钱包/订阅额度主要服务账号池分配；两者都不能直接替代外部渠道采购价、共享账号余额、费用预留、保守余额和账单差异处理，也不构成 FR-033～039 要求的采购侧订阅台账、共享额度识别和到期未用预测。

### 精确资源选择

AxonHub 用单渠道 Profile；ccLoad 用单 Channel allowlist Token；NewAPI 用单 Key Channel；Sub2API 用单账号 Group/API Key。OmniRoute 只有在 API Key 显式限制为单 Connection、Connection 只有一个 Key 时才精确。bestruirui/octopus 可用私有 model alias → 单资源 Group/Channel 构造 L0，但这不是正式 Channel Binding。所有方案都必须禁止执行平台在绑定内部自由轮换真实 Key。

## 5. 矩阵结论

没有任何候选可以直接满足 PRD。重新研究三个指定分支后，AxonHub 仍排名第一：其单资源 Profile 比 ccLoad Token、OmniRoute Connection 白名单和 Octopus model alias 更直接，且执行记录更接近 Attempt 语义。ccLoad 上调为轻量 L0 备选；OmniRoute 和 Octopus 的 L0 需要更严格的拓扑约束。动态首有效内容和财务级 Attempt 账本仍由外部组件负责。
