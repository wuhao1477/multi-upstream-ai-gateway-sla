## 贯穿全部决策的一条总原则

**策略参数一律"建议值作出厂默认 + 设置页可修改"**：设置页必须明示每项策略的含义、用法和修改影响；测活预算、禁测活规则等关键策略的修改需二次确认（用户确认理解设计后才能保存）。以下逐项记录中"可配置"均指此模式。

## 第二部分：16 项业务参数确认结果

| # | 参数 | 确认结果 |
| --- | --- | --- |
| 1 | SLA 指标 | **改为可配置**：SLA 等级的数量、各项指标数值、统计窗口全部由用户自定义（圈住的渠道不同，给的 SLA 就应不同）；建议的金/银/铜三级数值仅作默认模板 |
| 2 | 冲突优先序 | **改为可配置**：每个等级的 SLA/缓存/成本取舍顺序由用户自定义；建议顺序（金 SLA>缓存>成本、银 SLA>成本>缓存、铜 成本>缓存>SLA）作默认 |
| 3 | 测活预算 | 采纳（全局≤2% 月费用+日封顶、租户≤2%、会话≤1 次、失败≤错误预算 10%）；可配置，修改需二次确认 |
| 4 | 测活记账模式 | 默认全部业务严格补偿；设置中可全局切换为"预算延续"（成本优先），由用户决定 |
| 5 | 余额安全垫 | 采纳储备公式和 24h/6h/1h 三档处置，可配置。**余额不做实时查询**；新增需求：渠道"余额不足"信号自适应识别框架——各渠道返回余额不足的方式/状态机不同，需多策略适配（正则检测错误文案中的"余额"类关键词、真实请求查询账户/Key 余量是否归零等），优雅识别后触发处置 |
| 6 | 禁测活清单 | **不采用四条件清单**。并发重试原则上全局禁止（浪费大）；测活权限通过**对外模型别名**控制：把 SLA 策略编进模型名（如 `gpt-5.5-sla-1`、`sla-a-gpt-5.5`），调用哪个别名就适用哪套策略（含是否允许测活、SLA 等级），别名可自定义 |
| 7 | 全渠道不可用 | 采纳（金排队 15s、银 5s、铜不等待；不偷换模型），时长可配置 |
| 8 | 数据白名单 | **取消**。SLA 网关不处理请求内容，默认所有渠道可接所有请求；PRD 中"数据许可硬过滤"降级为可选功能 |
| 9 | 币种统一 | 统一美元口径；**一期所有币种 1:1 折算，币种仅作名称**，不建汇率机制（2026-07-23 明确） |
| 10 | 数据查询频率与过期 | 采纳建议值（价格 6h/24h/48h；余额校对 5～15min/30min/2h；订阅每小时、人工 7 天）作默认；可配置并说明影响。余额查询仅作后台校对（见参数 5） |
| 11 | 样本门槛与冷却 | 采纳建议值（1h≥20 次或 24h≥100 次；观察期 30min 或 50 次；冷却 5min 翻倍至 4h）作默认；**必须可配置**——用 SLA 网关的渠道普遍不稳定，建议值不一定适用所有人 |
| 12 | 容量保留 | 采纳（金级 20%、测活≤5%、接管保留金级峰值并发 10%），可配置 |
| 13 | 订阅台账字段 | 采纳建议字段（月费、生效/到期、周期额度、支持模型、倍率、重置规则、续订、超额计费、共享账号/Key；每字段标来源和更新时间，人工 7 天过期），另加**用满倍率**和**实际倍率**两个计算字段 |
| 14 | 订阅月费分摊 | **双倍率设计**：① 用满倍率 = 周期额度÷费用÷天数×分组倍率（按额度用满计算的边际成本口径），用于**调度排序**；② 实际倍率 = 按实际消耗重算，用于**账务和报表**（期中预摊、期末重算记差异）。理由：订阅固定费已付，边际成本趋零，用实际均价会错误降权未用满的订阅渠道。例：用满 0.034/实际 0.045 的订阅渠道，调度优先级应高于 0.035 倍率的普通渠道 |
| 15 | 订阅倾斜三道闸 | 采纳：成本≤最优普通渠道 1.5 倍；单订阅渠道≤该模型总流量 40%；仅剩余有效期≤7 天且预计浪费≥周期额度 20% 时启动 |
| 16 | 告警分级 | 采纳（P1 15 分钟/P2 1 小时/P3 当日），分类和时限可配置 |

## 第三部分：5 条新增需求确认结果（随 PRD v1.2 补入）

| # | 需求 | 确认结果 |
| --- | --- | --- |
| 1 | 自研决策核心可靠性 | 采纳：自身可用性≥99.95%、决策延迟 P99≤50ms、多实例部署、整体不可用时返回明确错误且**禁止旁路直连上游** |
| 2 | 对外 API 协议 | **只支持 OpenAI 两种格式：Chat Completions 和 Responses**；不做 Anthropic Messages。流式、工具调用、多模态字段透传，协议兼容性列入验收 |
| 3 | 审计数据保存 | 决策快照和费用账本存**元数据级**、保留 180 天可查询；**正文/用户上下文/请求头/请求体一期一律不存**（防数据库无限膨胀，后续版本再评估） |
| 4 | 上游 Key 存储 | **一期明文存储，不加密、不强制轮换**；保留既有 FR-094（日志和界面不显示完整 Key） |
| 5 | 系统规模 | **峰值 100～1000 QPS**。技术验证和容量规划按此量级；连带要求自研核心多实例与压测按此设计 |

## 对 PRD v1.2 的主要影响汇总

1. 新增"策略配置化"总需求：SLA 等级体系、冲突优先序、测活预算、数据时效、样本门槛、容量保留、告警分级均可配置，关键策略修改需二次确认。
2. 新增"对外模型别名即策略载体"需求：别名映射 SLA 等级与测活资格；并发重试默认全局禁止。
3. 新增"渠道余额不足信号自适应识别"需求（替代实时余额查询）。
4. 新增"订阅双倍率"需求：用满倍率参与调度排序，实际倍率用于账务。
5. 数据许可硬过滤（FR-001～006 相关条目）降级为可选功能，默认全允许。
6. 明确对外协议为 OpenAI Chat Completions + Responses。
7. 明确一期不存请求正文/上下文/头/体；账本元数据保留 180 天。
8. 明确一期 Key 明文存储；规模假设 100～1000 QPS。
9. 补入第三部分 5 条需求的确认版本；16 项参数以本记录数值为默认值写入。
