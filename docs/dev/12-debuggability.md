> **08 的结论在转向后变了**：当时判定"调试控制台属工具形态、不吸收"，前提是上游调用由 AxonHub 执行。现在自研透传层要自己处理 SSE 切分、首字判定、取消传播、usage 提取——**这些恰恰是最难凭日志排查的**，需要针对性的可观测手段。

---

## 1. 为什么现在需要（转向带来的排障缺口）

| 转向前 | 转向后 |
| --- | --- |
| 上游调用由 AxonHub 执行，有其管理界面 + `requests/executions/usageLogs` 可查 | **自研透传层执行，无任何现成界面** |
| 流式问题可对照 AxonHub 侧记录定位 | 只有我们自己的日志 |
| 协议差异由 AxonHub 消化 | 上游返回的怪异响应**直接打到我们脸上** |

自研透传层最容易出问题、且最难靠事后日志复原的三类：

1. **SSE 切分与首字判定**——内容感知 TTFT（AC-31）依赖逐事件解析；判错了指标全错，且事后无从复现
2. **取消传播**（AC-32）——取消有没有真的传到上游、上游何时停止产出
3. **usage / reasoning 提取**——上游格式各异（[07 §3bis](./07-axonhub-runtime-probes.md) 实测真实上游 35 字段、含 reasoning item）

## 2. 设计原则：在 FR-112 约束下做调试

**默认永不存正文**；调试能力靠"元数据 + 可控的临时开关"实现。

| 层级 | 内容 | 默认 | 存储 |
| --- | --- | --- | --- |
| L0 结构化指标 | 逐 attempt 的时序、事件计数、状态（[02 §4](./02-data-model.md) 已有） | **常开** | PG 账本 |
| L1 SSE 事件轨迹 | 每个流事件的**元数据**：序号、到达偏移(ms)、事件类型、是否含可见内容、字节数——**不含 text** | **常开**（内存环形缓冲，仅最近 N 条请求） | 内存，不落库 |
| L2 原始抓包 | 完整请求/响应正文 | **默认关闭** | 临时文件，带 TTL 自动清 |

L1 是关键设计：**只记"第 3 个事件在 517ms 到达、类型 output_text.delta、有可见内容、124 字节"，不记它说了什么** —— 足以复原首字判定与流时序，又不触碰 FR-112。

## 3. 借鉴 zhfeng1 的三点（思路，非代码）

### 3.1 SSE 事件解析（其 `parse_sse_events`）

它的解析按 `\n\n` 分块、逐行取 `event:` / `data:`，并统一 `\r\n`→`\n`。两个值得抄的细节：

- **换行归一化**：真实上游 `\r\n` 与 `\n` 混用，不归一会切错块
- **`data:` 多行拼接**：SSE 规范允许一个事件多行 `data:`，须 `\n` 拼接后再 JSON 解析

→ 直接用于我们 `executor` 的 `HasVisibleContent` 判定（[03](./03-upstream-layer.md)）。这两点做错，首字判定就是错的。

### 3.2 两段式延迟分解（其 `tps_from_values` / `gateway_overhead_ms`）

已在 [08 §5](./08-ref-eval-zhfeng1-ai-gateway.md) 采纳并落入 [02](./02-data-model.md)/[06](./06-deployment-and-operations.md)：

- 网关自身开销 = `总延迟 − 上游耗时`
- 生成速度分母 = `总延迟 − 内容感知 TTFT`（只算生成阶段）

### 3.3 抓取截断保护（其 `MAX_CAPTURE_BYTES` + `truncated` 标志）

它默认 `0`（**不限制**）——这正是 [08 §4](./08-ref-eval-zhfeng1-ai-gateway.md) 判定为反面教材的地方。我们**反过来用**：

- L2 抓包**默认关闭**；开启时**必须**设上限，超限截断并置 `truncated` 标志（宁可截断也不让磁盘爆）
- 抓包文件带 TTL，到期自动删除

## 4. 明确不做（防止调试功能膨胀成产品）

| 不做 | 理由 |
| --- | --- |
| WebSocket 实时请求列表 / 控制台 UI | 调试工具形态；我们有 [09 管理 API](./09-admin-api.md)，需要时查询即可 |
| 全量正文抓取常开 | **直接违反 FR-112**，且是凭证泄露面（zhfeng1 连 `Authorization` 都存） |
| 请求重放 | 一期不存正文，无从重放；且重放会产生真实费用 |
| 独立调试端口/服务 | 并入 `/admin/*`（[09](./09-admin-api.md)），不新增暴露面 |

## 5. 落地形态（M1 随上游对接层交付）

| 能力 | 形态 |
| --- | --- |
| L1 事件轨迹查询 | `GET /admin/debug/trace/{request_id}` —— 返回该请求各 attempt 的 SSE 事件元数据序列（内存缓冲，最近 N 条） |
| L2 抓包开关 | `config_params` 里的关键项（`is_critical=true`，需二次确认，[09 §3](./09-admin-api.md)）：`debug.capture.enabled` / `debug.capture.max_bytes` / `debug.capture.ttl_minutes` |
| 取消传播验证 | 事件轨迹里记录"取消发起时刻"与"上游连接关闭时刻"，直接印证 AC-32 |
| mock 上游复用 | `verify/mock_upstream.py`（role-only 首帧 / 空 SSE / 慢首帧 / 心跳 / 500 / abort）**转为自研透传层的测试夹具**——[11 §3](./11-decision-full-selfbuilt.md) 已说明其仍有效 |

## 6. 开放点

| # | 开放点 | 结论 |
| --- | --- | --- |
| 1 | L1 环形缓冲容量 | ✅ **已定**：默认最近 200 条请求，可配（内存占用可控，元数据每条约 KB 级） |
| 2 | L1 是否落库 | ✅ **已定**：**不落库**——账本已有 attempt 级指标（[02](./02-data-model.md)），事件级仅供实时排障，重启丢失可接受 |
| 3 | L2 抓包的凭证脱敏 | ✅ **已定**：抓包写盘前对 `Authorization`/`api-key` 等头做脱敏（即便一期 Key 明文存 PG，抓包文件也不重复暴露面） |
